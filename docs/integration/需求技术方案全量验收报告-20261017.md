## 技术方案校验及变更理由

| 原方案建议 | 实际采用 | 说明 |
| --- | --- | --- |
| Vue/TypeScript 可选 | 原生模块 + Vite/Three.js/GSAP | 方案允许保留现有工程；避免为换框架重做稳定界面 |
| FastAPI + SQLite | 已采用；匿名会话与进度由服务端持久保存 | 适合当前轻量服务；并发由限流与信号量控制，未宣称高并发容量 |
| MobileNet/ResNet 训练 | 默认云端图像理解；可选 CLIP 研究代码保留 | 用户已明确不要训练、不要给轻量服务器增加推理负担，因此不应再以“训练权重缺失”判定默认服务未接入 |
| BGE + FAISS | 可选 BGE 混合检索；默认结构化工具/词项检索，无 FAISS | 当前仅 34 条运行时知识，检索机制与原技术名词不同，不能声称已部署 FAISS；需要扩大资料与独立质量评测 |
| 单智能体工具调用 | 本站只读意图工具/检索 + Coze 输出 | 不等同于 Coze 平台上已经建立同名工具插件；平台内部配置需创建者导出 |
| /api/audio/speech | 实际规范为 /api/speech/tts | 前后端使用后一契约；OpenAPI 为真实字段依据，不声称原文示例路径全部原样存在 |
| 数字人/3D | 已有数字人/索道 GLB；三处场景预留模型和 POI 接口 | 不用概念画境替代精细模型验收 |
| 密钥仅后端 | 已填团队配置只由后端加载 | 私有仓库按负责人明确授权提交团队凭证；前端包无凭证，服务端不公开配置文件 |

## 本次发现并修复

| 缺陷 | 根因与修复 | 回归 |
| --- | --- | --- |
| 团队启动前端后历史长卷不可用 | npm run dev 原来只启动 Vite，未带起资料 API；增加 npm start / 联动 dev，自动创建环境、装依赖、加载配置、检查 health/history，端口冲突明确失败 | 干净副本 + 新依赖环境 + 浏览器实测历史成功；真实 Coze/识景/TTS 成功 |
| 请求失败只给笼统服务不可用 | 浏览器连接失败及 Vite 500 缺少恢复提示 | 提供本站后端与启动命令提示，新增回归 |
| 手机提交后看不到等待/回答 | 仍停留在输入区滚动位置；停止按钮在下方 | 提交、成功、失败重置回答区滚动；取消/重试移到状态附近；390px 检查可见 |
| 直接访问问山的介绍不匹配 | 文化目录异步到达后仅更新上下文标签，未更新介绍/推荐问题 | 目录到达后刷新内容，已提问则不覆盖回答；刷新大观峰链接实测 |
| 切景点后“这里”串入上一景点 | 追问拼接未区分新显式景点；上游提示未明确本轮位置 | 场景变化不继承上一景点问题，提示中明确当前名称；后端回归与真实上下文问答 |
| API 版本不一致 | health=1.7.1、OpenAPI=1.7.0 分别写死 | 同一 VERSION 常量，1.7.2；回归检查一致 |
| 团队部署模板较早 | Nginx 超时 50 秒短于 Coze 55 秒；未包含 text/javascript gzip | 模板统一 70 秒并增加类型，生产此前已有正确值 |
| 部分数字人控件热区过小 | 动作、关闭、朗读等按钮最小高度不足 | 统一至少 44px，保留既有视觉风格 |

## 真实 AI 验证的解释

本地与生产分别记录身份、景点列表、天外村路线、李白诗句、岱庙壁画、后石坞传说六类请求及来源。拒识样本为纯色测试图。实景样本来自项目现有图集，**不是独立测试集**；南天门样本可能同时返回十八盘，因此流程保留候选和人工确认，不宣传“准确识别率”。详见 JSON 中每次的请求、回答、mode、候选、耗时。

TTS 验证包括真实 MP3、三首诗缓存与服务提供方字幕边界；浏览器已观察实际播放器时间推进和对应诗行高亮。数字人模型自动化验证嘴部/手臂/手指网格变形；待机/动作与朗读分离。没有把静态截图当作麦克风或完整口型质量测试。

## 部署、性能与边界

生产已部署 1.7.2；[9 个变更文件哈希清单](full-audit-20261017/release-manifest.json)。备份位置 `/opt/taishan/runtime/before-full-audit-20261017`，含更新前入口、后端及一致 SQLite 备份；更新保留实时数据库与旧哈希资源。HTTPS 真实服务使用有效证书验证，未跳过 TLS 校验。

当前主 JS 约 781 KB、gzip 222 KB；Vite 仍有大于 500 KB 的 chunk 提示。已测接口实际耗时与静态资源完整性，**未完成慢网、真实手机帧率、LCP/INP/CLS 与持续负载容量测量**。云端响应受服务网络影响，单样本时长不是服务 SLA。

Windows 已增加双击启动及独立 HTTP 验收入口，目标 Win11 x64；[44 个 Windows x64 依赖 wheel 已完成下载解析，PowerShell 语法及两种安装控制流模拟通过](full-audit-20261017/windows-dependencies.json)。macOS/腾讯云测试不能替代 Win11 实机。最优先待团队补证的是：Win11 双击安装全过程、Chrome/Edge 麦克风权限与播放、实际显卡上的 WebGL。建模精细场景、文化专家签审及参赛实验也必须单列，不能随代码测试一起标“全部通过”。
