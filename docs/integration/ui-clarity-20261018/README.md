# 清晰度、画布与对话布局修订

设计依据仍为 `../UI设计图.docx` 中的 30 张图。用户补充的三张实际浏览器截图用于复现问题：地图缩小到 80% 露白、长回答与标题/上下文重叠、宽手机窗口的首页画面窄条居中。

## 实现与边界

- 公共导航恢复真实文字和 SVG 图标；首页标题、按钮、读山目录、山境目录标题、问山内容、红门介绍、历史与诗词的主要阅读文字独立渲染。复用现有路由、真实 API、收藏、语音与阅读行为。
- 地图以原画比例覆盖显示区。100% 是铺满窗口的最小尺寸；平移范围按实际画布和窗口差值计算，缩放或拖动均不露底色。普通滚轮只平移，缩放按钮、加减键、捏合和 Ctrl/Command 滚轮可缩放。地标与底图共用坐标变换。
- 问山改为“标题及上下文 / 独立滚动对话 / 输入框”三个布局行。所有动态消息按真实内容高度排布；历史记录独立滚动，底部插画有预留空间。长回答不进入标题与输入区域。
- 首页使用延展后的完整背景画布，移动端 `background-size: cover` 保持画面比例。309×767 原稿窗口与 532×752 宽手机窗口均核对。较宽窗口会展示新增两侧山景，极端窗口比例仍会自然裁剪。

这次没有将 Word 内的低分辨率插画宣称为原始高清素材。原字体文件没有提供，标题采用 OFL 字体 Ma Shan Zheng 的本地子集，正文沿用可用宋体/楷体。所有 30 张图的页面和状态仍可通过 [逐图入口表](../ui-design-20261018/README.md) 访问；该表中的旧版截图和像素一致性描述为历史记录，不代表本次修订逐像素零差异。

## 素材来源与复现

保留原稿山水、人物、照片和卡片插画。新增素材没有占位图。

1. `sources/welcome-cleared-desktop.png` 与 `welcome-cleared-mobile.png`：通过内置 `image_gen` 分别编辑原图，要求只移除中间标题、副标题、两枚入口按钮，填回同色云雾，保留人物、建筑、日出和小山徽。只按脚本列出的四组文字/按钮补丁合成；其他像素保留原图。
2. `sources/welcome-expanded-mobile.png`：通过内置 `image_gen` 单图横向延展，提示要求将 309:767 窄图居中扩展至 520:767，两侧各补约 105 像素的同风格云雾、山峰、松树与岩石，不新增文字/按钮/人物。最终资产重新覆盖原稿中间画面，边缘 32 像素过渡；保留的原稿核心范围为 `[137,0,382,767]`。两侧是生成的延展山景，不是 Word 原始素材。
3. `read-art-0..4.webp`、`read-hero-art.webp`、`read-continue-art.webp`：仅裁剪现有 Word 切片的插画区域，标题和按钮单独绘制。
4. 字体源：`https://raw.githubusercontent.com/google/fonts/main/ofl/mashanzheng/MaShanZheng-Regular.ttf`，OFL 许可在 `public/fonts/OFL-MaShanZheng.txt`；子集字符表在同目录，fontTools 生成约 66 KB TTF，无运行时新增依赖。

`python3 scripts/refine-native-ui-assets.py` 可重建本次 10 个插画资产并更新 [素材清单](../../../public/design-assets/manifest.json)。完整 Word 切片重建脚本也会调用它。源图均有本地留存；没有透明切图需求，输出为不透明 WebP。

## 验证

- 32 项单元测试和 Vite 生产构建通过；保留已有主 JS 包大于 500 KB 的提示。
- [主要操作回归](interactions.json)：引导、搜索定位、图集/大图、场景、手札、手机问山、设置、错误重试与转场通过。
- [清晰度检查](clarity-checks.json)：309×767、532×752、1211×810、1900×900，DPR 2；字体实际加载，导航/卡片文字可见，无文档横向溢出，首页画布完整覆盖窗口。
- [布局专项](layout-checks.json)：309×767、532×752、1024×600、1920×1080；缩放、滚轮、大幅拖动与复位后地图覆盖窗口，普通滚轮不改变缩放值；20 段长回答和多条历史记录不会与标题/输入框重叠。对话和历史使用明确测试响应，不写入真实用户对话。
- 整套页面回归仍覆盖 30 个设计编号、99 张状态截图，包含错误、保存、语音与识景状态。AI/ASR/TTS 和保存失败使用受控测试响应，不代表线上模型返回相同内容。

公网手机与当前窗口两组交互截图已核对；较大视口的公网批量自动化在浏览器输入阶段等待未结束，已停止，未计为通过。桌面及矮屏的交互采用本地同构建检查，生产文件逐一核对一致。

原图参考尺寸、当前用户窗口和更宽/更矮窗口均做了截图核对；标题、导航、长回答及滚动到底部另有局部/状态截图。桌面导航与移动端五项底部导航来自 Word，未另加新的导航结构。
