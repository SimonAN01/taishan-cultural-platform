# 泰山文化沉浸式网站｜建模手交付清单

版本：2026-10-16  
用途：供建模、美术与前端开发协作交付。  
首批场景：岱庙、彩石溪、后石坞。  
优先顺序：**先交岱庙一个庭院样板，确认空间和镜头后，再完成材质细节并扩展另外两处。**

## 一、制作目标与分工

目标体验：游客进入全屏三维场景，拖动观察、拉近细节、点击文化热点切换视点，展开文字与实景资料，并调用数字人讲解。

首版采用“环绕观察＋固定视点导览”。网站已有 GLB 加载、旋转缩放、热点投影及基础镜头切换能力；精细场景模型尚待交付。每个场景接入后仍需调整镜头、光照、遮挡与手机表现。

| 工作 | 建模／美术团队 | 前端／后端开发 |
| --- | --- | --- |
| 场景 | 建筑、地形、植物、道具、材质与贴图 | 模型加载、网页光照、显示与性能调整 |
| 导览 | 标注热点、建议观察视角、说明可展示范围 | 镜头切换、热点按钮、文字面板、返回逻辑 |
| 内容 | 提供模型参考、素材来源和待核实项 | 绑定文化资料、智能体、识图、语音和游历记录 |
| 验收 | 修复缺面、错位、贴图及导出问题 | 检查桌面与手机的实际交互及加载表现 |

**本单首批交付不包含数字人重新建模。现有数字人可继续使用。**

## 二、首批场景范围

| 场景 | 首版制作范围 | 网页模型文件 | 对应讲解主题 |
| --- | --- | --- | --- |
| 岱庙 | 一个建筑庭院单元，包含主体建筑、台基台阶、必要院墙、古柏及有依据的碑刻；先确认具体原型与院落范围 | `daimiao.glb` | 中轴礼序、壁画叙事、古柏碑刻 |
| 彩石溪 | 一段完整溪谷观察区域，包含彩石岩面、溪床、水道、岸边步道与必要植被 | `caishixi.glb` | 石纹地质、溪流水系、生态保护 |
| 后石坞 | 一个山岩、古松与祠宇组合单元；明确建筑原型，补齐允许观察方向的结构 | `houshiwu.glb` | 古松景观、山中祠宇、信仰传说 |

### 建模前确认

- [ ] 明确每个场景的实际原型、制作边界，以及是否允许环绕到背面。
- [ ] 用实景照片、可靠资料核对主要轮廓和空间关系。
- [ ] 首版岱庙以室外庭院为主；需要进入殿内时另行确认内景范围。
- [ ] 标出尚无资料、暂不制作或仅作艺术表达的部分。
- [ ] 现有“图片资产”“图片资产解压”可供美术风格参考；概念插画不作为建筑测绘依据。

### 文化表达约定

- 缺少壁画原作资料时，先保留壁画解说入口，不自行生成仿原作壁画。
- 没有清晰原文时，不在碑石上随意填入貌似真实的古文。
- 古松外形缺少具体资料时，不将通用松树模型标称为某一株真实名木。
- 生态和传说热点属于解说入口，不需要为它们虚构现场实物。

## 三、每个场景必须交付的文件

- [ ] **Blender 源文件 `.blend`**：可继续编辑，物体、材质和贴图组织清晰。
- [ ] **网页模型 `.glb`**：按上述文件名交付，能够独立加载，贴图内嵌。
- [ ] **贴图源文件**：单独归档，方便修改；源文件不能依赖制作人员电脑上的绝对路径。
- [ ] **预览图**：至少包含入口视角、整体视角、三个热点的建议视角；允许观察的侧面、背面也应能核查。
- [ ] **交付说明 `README.md` 或 `交付说明.txt`**：写明版本、原型、制作范围、模型尺寸、文件大小、三角面数、贴图规格、热点说明、已知问题及未完成内容。
- [ ] **素材来源记录**：列出照片、纹理、外部模型等来源及授权情况；团队原创的内容注明原创。

只交渲染图片或视频，无法支持网页中的三维环绕。必须同时交付可加载的 GLB 模型。

## 四、热点空物体命名——必须准确保留

请在 Blender 中用空物体标记热点，并随场景一起导出。名称区分大小写，不添加数字后缀，不改为中文。

| 场景 | 空物体名称 | 放置建议与用途 |
| --- | --- | --- |
| 岱庙 | `POI_axis` | 能说明建筑轴线与庭院秩序的可见位置 |
| 岱庙 | `POI_mural` | 壁画解说入口；缺少内景或原作资料时可放在殿前 |
| 岱庙 | `POI_trees` | 古柏与碑刻主题附近的可见解说位置 |
| 彩石溪 | `POI_stone` | 带状彩石清楚可见的观察位置 |
| 彩石溪 | `POI_water` | 能说明溪流、溪床与步道关系的位置 |
| 彩石溪 | `POI_fish` | 生态解说位置，不表示此处实际发现鱼群 |
| 后石坞 | `POI_pines` | 古松枝干与山岩关系清楚的位置 |
| 后石坞 | `POI_temple` | 祠宇主体可见的解说位置 |
| 后石坞 | `POI_legend` | 传说主题解说位置，不表示已证实的史迹 |

### 热点检查

- [ ] 每个 GLB 包含本场景对应的全部三个 `POI_*` 空物体。
- [ ] 热点属于导出场景的子节点，位置与模型一起保存。
- [ ] 热点放在希望显示讲解按钮的位置，不埋在模型内部或地面下方。
- [ ] 热点之间留有合理距离，避免默认视角下全部重叠。
- [ ] 给每个热点附一张建议镜头截图，并说明镜头应该看向哪里。

热点标记只定义讲解入口位置，**不等于镜头位置**。前端会根据建议视角另行配置镜头与遮挡处理。

## 五、模型与材质要求

### 几何与坐标

- [ ] GLB 使用 glTF 2.0；交付后的场景为 **+Y 向上，约定主入口正面朝 +Z**。
- [ ] Blender 可保持默认 Z 向上建模，使用 glTF 导出的坐标转换；最终核对 GLB 的朝向。
- [ ] 使用合理米制单位，应用必要的缩放，避免负缩放造成法线异常。
- [ ] `.blend` 保留有意义的原始尺寸；当前网页会将模型居中并按最大边统一缩放展示。
- [ ] 默认镜头和允许观察的方向没有明显缺面、悬空、错误法线或重叠闪烁。
- [ ] 台阶、屋脊、栏杆和主要树干等影响轮廓的结构使用必要几何表达。
- [ ] 不能仅用一张正面贴图代替需要环绕观察的主体建筑。

### 材质与贴图

- [ ] 使用能导出为标准 PBR 金属度／粗糙度材质的节点。
- [ ] 程序化材质、必要的 AO 和复杂表面细节先烘焙为贴图。
- [ ] 不依赖 Blender 专用着色器、未烘焙几何节点或体积效果在网页自动运行。
- [ ] GLB 内嵌所需纹理，不引用制作电脑的磁盘路径或临时外链。
- [ ] 普通 GLB 优先；可采用 Meshopt，**当前交付避免 Draco 和 KTX2**。
- [ ] 植物透明贴图、水面与双面材质控制数量，检查透明边缘与排序。
- [ ] 水面动画、风吹树叶、雾和粒子如需网页动态实现，在交付说明中单列；不默认 Blender 效果会随 GLB 自动生效。

### 初始性能目标

以下为首版制作目标，最终由真实手机测试决定是否需要进一步精简。

| 项目 | 初始目标 |
| --- | --- |
| 单个场景 GLB | 尽量控制在 3–8 MB |
| 单场景可见三角面 | 尽量不超过 10 万 |
| 主要贴图 | 1K–2K，按观察距离分配 |
| 材质与独立网格 | 合理合并，减少重复材质和无意义碎件 |
| 隐藏内容 | 不导出废弃对象、无关测试模型和看不到的高精度内部结构 |

若确有必要超过目标，请同时说明原因、体积和面数，交付一个可用于手机的轻量版本供比较。

## 六、镜头与交互资料

每个场景请附以下标注，可直接在预览图上说明：

- [ ] 默认入口视角：游客进入场景后第一眼看到什么。
- [ ] 整体观察视角：能看清主要空间关系的位置。
- [ ] 三个热点视角：说明观察对象与希望呈现的细节。
- [ ] 允许观察范围：哪些方向可以旋转，哪些区域暂未制作。
- [ ] 建议视点顺序：入口 → 热点一 → 热点二 → 热点三。
- [ ] 说明是否有建筑内部、屋顶或背面尚不适合展示。

如在 Blender 内保留相机，请命名清楚并附截图。当前网页不会自动采用 Blender 的相机、灯光、合成器或整段动画，需由开发配置接入。

### 仅在确认自由行走需求后追加

首批无需为未确认的自由行走额外制作整套系统。若后续确定需要，请补充：

- [ ] 可行走地面／步道网格。
- [ ] 墙体、台阶和场景边界的低面数碰撞简模。
- [ ] 出生点、台阶高度、禁入区与路线标注。

第一人称移动、碰撞检测和地面点击行走均需额外前端实现，不属于当前已完成能力。

## 八、分阶段交付与验收

### 第一阶段：岱庙灰模样板

- [ ] 提交原型参考与庭院范围。
- [ ] 提交能看清建筑、地面、台阶与树木关系的灰模 GLB。
- [ ] 包含三个正确命名的热点。
- [ ] 附入口及热点建议视角。
- [ ] 开发接入后，共同确认朝向、尺度、观察边界与镜头顺序。

### 第二阶段：岱庙精细版

- [ ] 按确认后的空间关系制作细节与材质。
- [ ] 交齐源文件、贴图、GLB、预览与来源说明。
- [ ] 修复网页接入后发现的缺面、材质和观察死角问题。
- [ ] 桌面与手机联调通过后，作为另外两处场景的交付样板。

### 第三阶段：彩石溪与后石坞

- [ ] 沿用已确认的格式、热点与性能要求。
- [ ] 分场景提交、分场景验收，避免最后一次性发现共性问题。

### 最终共同验收

- [ ] 在另一台电脑打开 `.blend`，无丢失贴图。
- [ ] GLB 独立加载，无外部素材路径缺失。
- [ ] 九个热点名称与三个场景一一对应，无遗漏或重复。
- [ ] 默认镜头、旋转、缩放及热点切换无明显穿模、出界或主体消失。
- [ ] 文化热点与文字对象对应，未将概念画面或传说表述为精确复原。
- [ ] 手机实际检查画质、加载、操作和运行流畅度，记录设备与结果。
- [ ] 文件大小、三角面数、贴图规格、授权来源和已知限制记录完整。
