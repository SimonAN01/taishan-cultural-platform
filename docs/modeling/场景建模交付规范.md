# 场景建模交付规范

当前前端已支持 Three.js 透视视口、鼠标/触控旋转、缩放和视点复位。精细 GLB 加载后按 POI 显示空间热点并切换镜头；概念画境使用画面外的主题导航与依次导读，不把概念坐标当作实物位置。现有图片形成的是分层空间画境，不能代替完整的三维建筑或真实地理数据。精细建筑背面、内部、台阶连接、栏杆和屋顶结构交由建模师完成。

## 本轮优先交付

| 模型 | 推荐制作范围 | 输出文件 | 必须包含的热点空物体 |
| --- | --- | --- | --- |
| 岱庙 | 一个可环绕观察的建筑庭院单元；确认名称后再制作精细檐口、门窗、台基与院落关系 | `daimiao.glb` | `POI_axis`、`POI_mural`、`POI_trees` |
| 彩石溪 | 溪谷岩面、水道、岸边步道、古松或植被；使用实景参考控制岩层结构 | `caishixi.glb` | `POI_stone`、`POI_water`、`POI_fish` |
| 后石坞 | 山岩、古松和祠宇组合单元；核对庙宇外形，补齐背面与观察死角 | `houshiwu.glb` | `POI_pines`、`POI_temple`、`POI_legend` |

热点空物体标记讲解视点，不一定对应实物。例如 `POI_fish` 是生态解说停留点，不能凭空做成真实鱼类观测点；`POI_mural` 可先放在殿前作为壁画解说入口，没有原作资料时不生成假壁画；`POI_legend` 是传说解说点，不代表史迹定位。

参考素材见用户的“图片资产”“图片资产解压”目录与仓库 `src/image-assets.json`。现有平面建筑图是概念参考，不能当作准确测绘图。请先确认要复原的具体建筑及实景参考；复杂部分宁可分期，也不制作貌似精细的错误结构。

## 文件约定

- 主文件：Blender `.blend`，保留物体、材质、贴图、灯光组织；网页交付：glTF 2.0 二进制 `.glb`，贴图嵌入，避免外部网络依赖。
- 坐标：glTF +Y 向上、正面朝 +Z；建模时使用合理米制单位，应用缩放。网页会按模型最大边统一缩放为 7 个场景单位并居中，保持整体方向。
- 热点：用空物体命名为表中 `POI_*`，作为模型场景树的子节点，放到可观察的位置。网页会读取世界位置投影热点并切换镜头。
- 材质：标准 PBR 金属粗糙度；烘焙必要的纹理和 AO。不要依赖 Blender 专用节点、实时体积雾或几何节点在网页自动运行。
- 支持：普通 GLB、Meshopt 压缩；当前未接 Draco/KTX2 解码器，交付前避免这两种压缩。
- 初始预算建议：单场景先争取 GLB 3–8 MB、可见三角面 10 万以内、主要贴图 1K–2K、材质数尽量少。预算是制作目标，最终以真实手机测试决定，不代表已测性能。
- 水面优先轻量材质；石阶、屋脊和栏杆用真实几何表现轮廓。避免把全部细节烘焙成一个正面平面而声称可环绕。

## 如何接到网站

三个文件分别放到前端 `public/models/scenes/`。本地构建后会出现在 `dist/models/scenes/`；服务器路径为：

```text
/opt/taishan/immersive/models/scenes/daimiao.glb
/opt/taishan/immersive/models/scenes/caishixi.glb
/opt/taishan/immersive/models/scenes/houshiwu.glb
```

后端目录与场景接口会检测对应文件，刷新页面后自动启用 GLB 分支，不需要把模型服务或推理服务部署到轻量服务器。模型读取失败时保留分层画境；切换“画卷阅读”后可重试。

当前 GLB 加载分支已用临时测试几何验证可加载、缩放和读取热点。该测试模型已移除，不在 Git 或服务器发布包中。尚未交付上述精细场景模型，不能以已完成精细三维复原参赛宣传。

## 接收检查

1. 打开 `.blend`，确认贴图齐全、命名正确、模型不是只有正面。
2. 加载 GLB，检查旋转、尺度、透明面、法线、光照、热点位置和镜头是否穿模。
3. 检查桌面与手机拖动、缩放、热点讲解、返回、语音；检查加载失败后能恢复画卷。
4. 记录文件体积、面数、实际设备与浏览器、加载时间、照片/纹理的来源授权。

当前视口提供环绕和热点导览，尚未实现建筑内部第一人称行走、碰撞检测或真实地理导航。若后续需要这些交互，请在建模前额外交付可行走地面与碰撞简模，避免返工。
