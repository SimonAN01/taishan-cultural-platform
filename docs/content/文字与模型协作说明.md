# 文字与模型协作说明

2026-10-16 · 1.7.1

前端沿用已确认的山水长卷、纸本阅读和朱砂操作色。本轮补齐阅读线索与返回逻辑，不更换视觉体系。轻量服务器继续负责资料、会话与云端 API 转发，浏览器负责场景渲染。

## 本轮文字

- 19 个景点：`taishan/data/catalog.json` → `spots[].reading`，包含导读标题、看什么、读出什么、追问、关联地点。
- 7 条历史记录：同文件 `history[].reading`，包含阅读角度、说明与追问。
- 3 首诗：同文件 `poems[].reading_path`，每首三个阅读节点，`line_index` 从 0 开始，对应原诗的实际行。
- 原诗、22 行注释、历史概述、来源与已有文化场景保留。本轮导读仅整理现有资料中的线索，没有新增未经核验的年代、人物事件或考古结论；页面注明 AI 辅助与待人工复核。
- 团队提供的审定文字可直接替换上述字段；保留条目 `id`、正确来源和行号，页面与接口继续共用同一份内容。修改原诗时应同步核对注释、导读行号与朗诵时间缓存。

## 已串联的流程

首页五章读山 → 景点阅读 → 返回原章节 → 答题保存 → 下一章 → 三卷山境。首次进入自动解析服务器的下一章，并将实际章节写入 URL；景点、诗词刷新后仍可返回该章。

历史导读 → 带入问题和景点的问山输入框 → 用户提交 → 关闭回到原朝代。

诗词三步导读 → 定位原诗行与注释 → 继续追问或转入历史/游历。手机默认折叠导读，保留正文阅读空间。

景点 → 主题关联地点 / 路线 / 游历。关联地点仅表达阅读主题，页面明确它们不是相邻步行路线。存在近景的地点使用“走近画境”；缺少近景的地点直接返回地图，避免原地重开。

## 3D 资产分工

团队负责精细场景建模、贴图与渲染美术。我方负责浏览器模型加载、镜头、热点、文字、问答与语音联动。

- 交付规范：`docs/modeling/场景建模交付规范.md`，包含 GLB 文件名、POI 命名、坐标与材质要求。
- 首批场景：岱庙、彩石溪、后石坞，各三个已有阅读热点。
- 当前上线空间画面为真实透视镜头下的分层概念素材；三处精细场景 GLB 尚待团队提供。已有数字人、索道三维模型与手动动作可继续使用。
- 接入 GLB 后逐项验收镜头、遮挡、热点、手机帧率与载入；不能把当前分层画面表述成已完成精细三维重建。

## 验证

本轮完成 27 项前端测试、33 项后端测试（其中 1 项可选 CLIP 检查跳过）与生产构建；桌面 1280×720、手机 390×844 检查了导读、诗句跳转、关联阅读、历史提问返回、首次章节解析、景点刷新返回与真实答题保存。截图位于 `docs/integration/screenshots/frontend-content/`。

主 JS gzip 约 222 KB；本轮没有新增依赖或重传大图与模型。该大小是构建输出，不代表真实用户网络性能。云端模型抽查记录与部署哈希另存于发布记录，不能视为全面识景准确率评测。
